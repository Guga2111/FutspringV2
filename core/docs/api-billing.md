# API: platform admin and subscription

> The platform admin panel and the creator's subscription area. Part of the [backend guide](README.md).

All routes are under `/api/v1`. "Auth" is the relationship checked (see the matrix); the invitation-link preview and the e-mail preference links are also public (see below).

## Platform admin (`PlatformController`, `/platform`)
The operator's panel. Every service method starts with `PlatformAccess.requirePlatformAdmin` (404 "Recurso não encontrado" to anyone else; a malformed body or id still answers 400 first: the panel's routes are no secret, the web app's bundle names them, only its data is). Commands lock the pelada row (`findByIdForUpdate`, the lock of the pelada's other writes) and go through `SubscriptionService`, which records a `SubscriptionEvent` with the kind and validity before and after, the actor and the note. Money is an exact two-decimal string. Dates of the billing are in `America/Sao_Paulo` (`SubscriptionService.BILLING_ZONE`); "end of the day" is 23:59:59 there. Lists: `page` ≥ 0, `size` 1–50 (default 20), `{items, total}`.

| Method | Path | Body | Response |
|--------|------|------|----------|
| GET | `/platform/overview` | — | `{counts: {TRIAL, ACTIVE, PAST_DUE, READ_ONLY, PENDING, EXEMPT}, trialsEndingSoon: [{id, name, date}] (trials ending in 7 days, soonest first, ≤ 20), pixClaimed: [{id, name, date}] (oldest claim first, ≤ 20), revenueThisMonth, revenueByMonth: [{month: "yyyy-MM", total}] (12, the current month last), recurringEstimate (per month: the payments not voided whose period covers now, of peladas still `PAID`, annual ÷ 12), users: {total, last30Days} (not deleted; by `createdAt`)}`. Constant queries: one count per state (`SubscriptionStatusFilter`) and one per block |
| GET | `/platform/peladas?state=&q=&page=&size=` | — | `{items: [{id, name, creator: PublicUserDTO, memberCount, status, validUntil, founder, pixClaimedAt, lastSessionDate (last FINISHED session)}], total}`, by pelada name. `state` = an effective `SubscriptionStatus`, translated to SQL over `kind` + `valid_until` with the same edges as `SubscriptionState`; `q` matches the pelada, the creator's name or e-mail (case-insensitive). Peladas without a subscription row are not listed. Four queries whatever the page |
| GET | `/platform/peladas/{id}` | — | `{pelada: {id, name, image, creator: PublicUserDTO, creatorEmail, memberCount, lastSessionDate}, subscription: {kind, status, writable, validUntil, plan, founder, pixClaimedAt, claimedPlan, prices: [{plan, amount}] (list prices for its member count), createdAt, updatedAt} \| null, payments (latest 50, voided included), events (latest 50, newest first: {id, type, actor: PublicUserDTO \| null, kindBefore, kindAfter, validUntilBefore, validUntilAfter, note, createdAt})}`; 404 unknown pelada |
| POST | `/platform/peladas/{id}/payments` | `RecordPayment {plan @NotNull, amount "19.90" (> 0, ≤ 8 integer digits), paidOn (not in the future), note ≤ 500}` | the detail. `PAID` with the plan until the end of the day one month / year after `max(now, validUntil)` (`validUntil` only counts while a trial or paid period runs), so paying early never loses days; the Pix claim is cleared; the payment stores the pelada and creator names, the period and who recorded it |
| POST | `/platform/peladas/{id}/subscription` | `ChangeSubscription {action, validUntil?, days? (1–366), founder?, note ≤ 500}`; `note` required except for `SET_FOUNDER` (400 on `note`), each action's own field too | the detail. `SET_VALID_UNTIL`: `PAID` until the end of that day (a past one locks). `EXTEND_DAYS`: `max(now, validUntil)` + days, the kind kept; only `TRIAL`/`PAID` (else 409). `EXEMPT` / `CANCEL`: no end date any more (exempting also clears a Pix claim). `SET_FOUNDER`: the flag |
| POST | `/platform/payments/{id}/void` | `VoidPayment {reason @NotBlank ≤ 500}` | the payment; it leaves every total and the validity is unchanged (adjust it apart); twice → 409; the payment row is locked. A `PAYMENT_VOIDED` event while the pelada exists |
| GET | `/platform/payments?from=&to=&page=&size=` | — | `{items: [payment], total, sum}`, newest `paidOn` first; ISO dates inclusive on `paidOn` (`from` after `to` → 400 "Período inválido"); `sum` leaves voided payments out, the list doesn't |
| GET | `/platform/users?q=&page=&size=` | — | `{items: [{id, username, email, createdAt, peladasCreated: [{id, name}], memberOf, trialUsedAt, isDeleted}], total}`, every account (deleted included), newest first; `q` matches name or e-mail. Four queries whatever the page |

## Assinatura (`SubscriptionController`, `/peladas/{id}/subscription`)
The creator's side of the subscription. Both routes: unknown pelada 404, anyone but the creator 403. Money is an exact two-decimal string.

| Method | Path | Body | Response |
|--------|------|------|----------|
| GET | `/peladas/{id}/subscription` | — | `PeladaSubscriptionDTO {status, validUntil, plan, founder, pixClaimedAt, claimedPlan, pixRecipient, plans: [{plan, amount, pixCode}], payments: [{paidOn, amount, plan, periodEnd}]}`. `plans`: the list price of each plan for the pelada's member count, each with its static Pix BR Code ("Copia e Cola", also the QR Code's content: the amount and the txid `FUT{peladaId}`); `pixRecipient` and every `pixCode` are null without `BILLING_PIX_KEY`. `payments`: the latest 20, voided ones left out. Four queries |
| POST | `/peladas/{id}/subscription/pix-claim` | `PixClaimRequestDTO {plan @NotNull}` | `PeladaSubscriptionDTO`; see the Pix claim in [Subscriptions](subscriptions.md#subscriptions-domainsubscription). 409 for an exempt pelada or without a configured Pix |
