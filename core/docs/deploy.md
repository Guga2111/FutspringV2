# Deploy and backups

> The CD workflows, nginx, GitHub secrets and the database backup. Part of the [backend guide](README.md).

## Rules

1. Production changes only through the CD workflow and `scripts/deploy.sh`; secrets come from GitHub / `.env`; `DDL_AUTO` is never set.
2. nginx changes go to `ops/nginx/futspring.conf` first, then are applied by hand; `X-Forwarded-For` is always overwritten, never appended.
3. Publication waits for the pre-deploy backup gate.

## CI/CD

- `.github/workflows/deploy.yml` runs on every push to `main` (and manually): it waits for backend, frontend and backup-tooling CI, writes `.env` from the GitHub secrets, runs `scripts/deploy.sh`, then smoke-tests `APP_URL` (200) and `<API_URL>/readyz` (200 through nginx, so a wrong `API_URL` prefix fails too), and finally that `/` and `/home` carry `Content-Security-Policy: frame-ancestors 'none'` (anti-clickjacking; fails at once, without retries, when the live nginx drifted from `ops/nginx/futspring.conf`).
- `scripts/deploy.sh` builds the frontend and amd64 API image, then requires the host-only shared `ops/backup/backup.py pre-deploy` gate **before frontend rsync, new `.env` publication or API/Flyway startup**. Missing configuration, unverified offsite copies or unknown/insufficient budgets block publication. It then copies the image/compose/`.env`, creates the observability network and private file mounts (uid 10001), starts compose and waits up to 2 minutes for Redis and API health. It refuses `DDL_AUTO`. Existing local `backups/*.sql.gz` are preserved; the optional `PG_DUMP_URL` fallback is removed. See the [backup runbook](../../ops/backup/README.md): tooling is installed but **operational acceptance remains pending**, and deploying this gate to `main` requires operational preparation first.
- `.github/workflows/deploy-observability.yml` deploys the shared Prometheus + Grafana stack (`ops/observability/`, see its README) on pushes to `main` that touch it, independently from the API. It also supports manual runs on `main` after secret creation/rotation (secret changes do not trigger a deploy). Its smoke test requires the Telegram contact point and all alert rules, Grafana health, Loki readiness and the stack targets; the job has read-only repository permissions and a 15-minute timeout.
- **nginx (manual, on the VPS; `deploy.sh` doesn't touch it):** the site is versioned in `ops/nginx/futspring.conf` (copied from the VPS's `/etc/nginx/sites-available/futspring`; the header comment has the `scp` + `nginx -t && systemctl reload nginx` steps). Change it there first, then apply it by hand. What it carries:
  - `/api/` → `http://127.0.0.1:8081/` (the trailing slash strips `/api`) and `/ws/` with the WebSocket upgrade; both **overwrite** `X-Forwarded-For` with `$remote_addr` (never `$proxy_add_x_forwarded_for`, which appends to what the client sent) and set `X-Real-IP` / `X-Forwarded-Proto`. The rate limits depend on it (see [Rate limiting](security.md#rate-limiting)).
  - PWA cache: the service worker updates only when the browser sees a new `sw.js`, so `sw.js`, `manifest.webmanifest` (served as `application/manifest+json`) and `index.html` (the SPA fallback included) go out with `Cache-Control: no-cache`; the hashed files in `/assets/` keep `public, max-age=31536000, immutable`.
  - gzip for JSON, JS, CSS, SVG and the manifest (`gzip on` is in `nginx.conf`, whose default types are only `text/html`), from 1 KB.
  - **Content-Security-Policy:** the policy is a `<meta>` of `index.html` written by the frontend build with the theme script's hash (see [Content-Security-Policy](../../client/docs/design-system.md)), so it ships with every deploy and reaches installed PWAs. nginx only adds `Content-Security-Policy: frame-ancestors 'none'` on `location = /index.html` (every document of the SPA lands there; an `add_header` inside a location drops the server-level ones), the one directive a meta tag can't carry. The deploy's smoke test fails when it is missing. Violations reach Loki: the web app sends each one to `POST /client-errors` with source `CSP` (`event=client_error`). The API's responses carry no CSP (JSON only; Swagger is off in production).
- Locally: put the production values in `.env` at the repo root (gitignored, keys in `core/.env.example`) and run `VPS_IP=… VITE_API_URL=… ./scripts/deploy.sh`.

## Database backup and recovery

`ops/backup/` contains the shared daily/pre-deploy PostgreSQL custom-archive backup, private host configuration examples, disabled-by-default systemd installation and a networkless disposable restore drill. A verified TLS read-only snapshot includes public objects and Flyway history; archive and manifest are downloaded and checked before success. RLS flags are preserved and validated; filtered reads and unreviewed policies block backup. The dedicated reader needs complete SELECT and BYPASSRLS for the current `users` table, without changing application RLS. Daily schedule: 03:00 America/Recife, daily retention 30 days, pre-deploy 7 days, seven-day R2 bucket lock. Real offsite backups and independent owner-account download/isolated recovery passed on 2026-11-20. After explicit owner authorization, the timer was enabled on 2026-11-21 and an ordinary systemd execution verified a new copy. Keep the reviewed PostgreSQL client image staged: jobs never pull implicitly. The budget ledger needs authoritative reconciliation within 24 hours; the timer does not refresh it. Ongoing budget maintenance and release of the committed deploy gate remain pending; activation is not full operational completion.

Account-wide storage/request reservations and measured Supabase egress envelopes fail closed. The local 8 GB ceiling **does not guarantee zero billing**. The owner subsequently accepted R2 metered-billing exposure; the private activation record must reflect that decision without claiming a zero-cost guarantee. Known budgets, real verified backup/restore, Telegram delivery and operational acceptance remain required; no paid Supabase upgrade or recovery target is authorized. Recovery and planned migration are manual, with writes stopped and a fresh final backup before planned cutover; files/photos/Redis are outside scope. Commands, budget reconciliation, legacy backup preservation and acceptance steps: [runbook](../../ops/backup/README.md).
